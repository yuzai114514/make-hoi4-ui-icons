# 验收与返修

制作前用本页明确终点，交付前检查实际最终文件。目标是让用户第一次看到已完成基本质量控制的成品；审美仍可讨论，但可见的结构、遮挡、边缘、文字和导出错误应在制作中消除。仅评审或仅提供提示词时不扩大为制作任务。

## 什么才算完成

以下条件与请求的产物范围相匹配后才能交付：

1. **内容与表达成立。** 身份、用户明确约束与实际实现状态正确；主次、比例、朝向、动作及前后关系可读，关键脸部、手势和物件没有误遮挡、缺块或切片残留。国策看得出相关政策、动作或变化；若只剩宽泛类别，检查是否需要调整主体关系，不要求每张图都讲完整故事或唯一反推出标题。
2. **风格、加工效果与可读性成立。** 缩到游戏实际尺寸，对照加工前的同构图和已查看的同类参考，检查加工是否真正改善了所需的视觉重心、材质和前后关系，同时保留原料中有用的形体与表现力。若主要变化只是整圈描边与统一调色，仍须继续处理，不能以轮廓更亮、颜色更浓或没有明显错误判定完成。图内文字含义合适、无错字漏字、笔画可辨，字效与排版不妨碍阅读；名称文字清楚。原料本身已经成立的部分可以保留，不为证明加工量而重复叠效果。
3. **最终文件确实检查过。** 实际运行适用的导出与验证工具，打开最后一次导出的 PNG 查看，而非只看提示词、PS 工作区或旧预览。图标尺寸、alpha、透明区、文件路径和来源记录符合约定。通过 Photoshop 制作或修改的产物，实际保存并重开 PSD，确认图层、智能对象、文字与蒙版仍可编辑且显示结果对应导出；直接复用已有成品不强造 PSD。整张 GUI 和肖像按各自规格检查，不强套透明图标校验。
4. **已发现的问题已闭合。** 修复发现的明显问题，重新导出，并复查修改部位及其影响到的构图、缩放、遮挡或文字；最终检查对应当前版本。普通返修在本次任务内继续，不以“请用户先看看”作为中途停止点。

“已加倒角”“有很多图层”“技术检查通过”“比旧版改善”只能证明对应动作或局部结果，不能替代以上条件。也不需要为了显得认真而重复已通过且未受影响的检查。

## 用哪些视图发现问题

- **放大细节：** 看抠图残边、错误孔洞、手指与接触点、切片杂物、字形和字内空隙；最终排层后检查蒙版、剪贴范围及组效果是否错盖其他对象。只看层是否存在不够。
- **实际尺寸、深底与浅底：** 看主体是否过小、主次是否混乱、文字是否清楚、亮边或阴影是否过重、加工是否缩小后消失。alpha=0 内的隐藏 RGB 不代表背景残留，以实际 alpha 合成结果判断。
- **带目标名称框或槽位：** 国策把最终图标与名称放到同一预览检查，肖像放入对应头像框，其他类型按实际槽位。原尺寸版本必看，放大版本只辅助。GUI 参数可取时按实际位置；框外观或字体近似时注明。前景是否压框取决于用户要求和目标界面，不能为了压框擅自取消默认透明区；允许压框时仍保护名称字形区域。
- **原料、最终版、风格参考：** 用同一构图、显示大小与背景比较加工前后，辨别收益来自主体内部的明暗、材质与遮挡关系，还是仅来自外围轮廓。指出实际图上可见的改善与仍存问题；操作名称和加工说明不能替代这种差异。与历史版本比较时另行标明版本来源，不拿本轮首稿代替上一轮成品。已有对比图可复用，无需固定张数或另建表格。

## 发现问题后继续做什么

按问题所在阶段返修：主题或主次不清回到构图，手势和形体错误修原料或局部蒙版，素材风格分裂调光色与材质，字难认先查字形和排版再调字效。显空先调比例与间距，避免自动填充装饰。结构明确且可用时在 PS 局部修改；需要重做形体时才生成相应素材。

保存必要旧稿后修改，导出并检查新结果；不是一轮结束就交稿，也不是固定跑满若干轮。条件满足便交付，不为无法验证的“绝对完美”反复重做。连续修改不再改善时，重查原料与构图假设，不能只继续叠加效果。

确实因必需工具不可用、必需输入缺失或不可兼容的用户约束无法完成时，报告具体阻碍、受影响的检查和可审查成果。不要把普通美术选择包装成阻碍，也不要在已知明显问题未修复时宣称完成。

## 记录与交付状态

沿用任务现有记录，以当前文件路径或版本标明检查对象，写具体观察、修改及复查结果，不强制新增报告层级。保留原料、真实提示词与参考角色、可编辑 PSD、必要旧稿和对比。生成素材记录在 `generation.json`，来源沿用 `sources.json`。

技术结果由工具证明；视觉自检来自实际看图。无人看过时为 `pending`，有未修复问题为 `needs_revision`，完成上述自检后可记为 `self_review_passed`；旧格式的 `accepted` 必须注明只代表谁、哪一项检查。导出、打包或生成预览不能自动赋予或沿用视觉通过状态；修改图像后原视觉结论待对应复查。

用户验收只有用户实际确认才记通过。游戏内验证只有在用户已要求或授权运行游戏、实际载入对应界面并检查后才记通过；离线预览与静态引用检查不替代它。未请求游戏验证不妨碍完成独立图标交付；若已请求，则把运行、检查与修复纳入完成条件，有真实阻碍时明确报告。
